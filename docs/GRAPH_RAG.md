# SafeOps GraphRAG

FAISS의 의미 검색과 출처 기반 속성 그래프의 다단계 조회를 결합한다. 그래프는 JSON으로 직렬화하지만 검색 시에는 노드 ID별 인접 목록을 구축하고 방향성 간선을 BFS로 탐색한다. 별도 그래프 DB 서버나 Microsoft GraphRAG 패키지는 사용하지 않는다.

## 이번 보완의 목적과 처리 순서

사용자의 짧은 상황 설명에서도 `물질 식별 → 위험기호·신체 주의 → 상황별 대응 → 보고 절차 → 담당 부서 + 병원`을 연결한다. 검색 결과에 들어온 근거와 실제 모델에 전달한 근거를 구분하며, 답변의 연락처 누락도 후처리로 보완한다.

| 이전 문제 | 변경 | 목적 |
| --- | --- | --- |
| 염산이 카탈로그의 염화수소와 연결되지 않음 | 염산·HCl·hydrochloric acid 별칭과 CDC 출처 기록 | 이름 차이로 물질 페이지가 빠지는 문제 해결. 수용액·농도 조건은 별도 유지 |
| ‘가스가 누출’, ‘새고 있어’가 누락됨 | 조사·구어체 누출 표현 처리 | 29~30쪽 연속 지침 연결 |
| 운반·사용 전·폐기 준비 근거 부족 | 12·20·25·43쪽 원문 구간과 handling/transport 경로 추가 | 요청 단계에 해당하는 지침 확보 |
| 위험기호가 설명으로 연결되지 않음 | 검토된 그림 → 공식 코드 → 일반 의미 → 신체 노출 지침 후보 | 기호는 내부 근거로 활용하고 위험성·주의사항만 답변 |
| 담당 부서만 있거나 병원 번호 누락 | 물질 → 안전 업무·병원 연결, 컨텍스트 우선 예약, 답변 연락처 후처리 | 두 연락 대상을 각각 안내 |
| PDF만으로 물질별 건강 정보 부족 | CAS 기반 Naver 웹문서 검색 + CDC/NIOSH CAS 색인 fallback | 공식 원문의 신체 영향·주의사항 보완 |
| 평가가 모델에 전달하지 않은 후보까지 포함 | `context_results`를 생성·인용 검사·RAGAS에서 공통 사용 | 실제 답변 근거만 평가 |
| 관련성 점수의 원인을 추적할 수 없음 | 평가 모델의 역생성 질문·판정 출력을 `details`에 저장 | 낮은 점수를 사례별로 설명 가능 |

## 생성과 저장

`prepare`가 본문/구조화 청크, 물질 카탈로그, 절차·연락망 스냅샷, 문서 연결에서 그래프를 생성한다. `build`는 그래프와 운영 시간 정책을 FAISS와 같은 인덱스 버전에 복사하고 파일 해시를 기록한다.

```text
indexes/<build_id>/
  index.faiss
  documents.jsonl
  material_catalog.json
  structure_snapshot.json
  document_links.json
  operating_policy.json
  knowledge_graph.json
  manifest.json
```

그래프는 `nodes`, `edges`, `evidence`, `operating_policy`, `statistics`로 구성한다. 노드와 간선은 안정적인 ID를 갖고, 출처 청크를 `evidence_ids`로 참조한다. 간선마다 `basis`에 PDF 페이지·절차도 화살표·전사 관계·검색 라우팅 정책 중 생성 근거를 기록한다.

노드 유형은 물질, 사고 유형, 절차 경로, 절차 단계, 기관 범위, 조직/부서, 업무, 조직별 업무, 연락처, 위험기호, 원문 근거다. 현재 원문으로 생성한 그래프는 516개 노드/525개 간선이며 물질 50개, 절차 경로 3개, 단계 19개, 연락처 8개를 포함한다.

## 주요 관계

| 경로 | 생성 근거 |
| --- | --- |
| 물질 → 원문 근거 (`described_by`) | 카탈로그의 물질 페이지 |
| 물질 → 사고 주제 (`has_guidance_topic`) | 해당 페이지의 ‘누출시’, ‘화재시’ 제목 |
| 사고 유형 → 대응 원문 (`has_guidance`) | 기존 문서 연결의 주제 경로 |
| 원문 → 연속 구간/제한조건 | 기존 문서 간 출처 관계 |
| 사고 유형 → 보고 절차 (`reporting_procedure`) | 명시적 검색 라우팅 정책 |
| 절차 → 단계 (`contains_step`) → 다음 단계 (`next_step`) | 전사된 경로와 화살표 |
| 사고 유형 → 업무 (`related_work`) | 명시적 검색 라우팅 정책 |
| 업무 → 조직별 업무 (`provided_by`) → 연락처 (`has_contact`) | 연락망 레코드 |
| 연락처 → 조직 (`belongs_to`) → 기관 범위 (`within_institution`) | 연락망 레코드 |
| 절차 단계 → 관련 연락처 | 기존 `role_links.json`의 관계·검토 상태 |

물질이 어떤 사고를 실제로 일으킨다는 관계를 자동 생성하지 않는다. 물질에서 사고 유형으로 향하는 간선은 그 물질 문서에 해당 주제의 지침이 있다는 뜻이다. 사고 유형과 업무/보고 경로의 연결은 PDF 사실과 구별해 `basis=retrieval_policy`로 기록한다.

## 조회

1. 물질명·영문명·CAS를 매칭하고 질문의 사고 주제, 직접 언급된 업무/조직을 진입 노드로 선택한다.
2. 방향성 인접 목록에서 BFS를 수행한다. 기본 최대 5 hops, 허용 범위 1~8 hops다.
3. 기관 범위, 명시적 사고 분류, 지정 시각의 연락 가능 시간으로 탐색을 필터링한다. 사고 분류가 생략되면 각 분기 조건을 보존해 경로 후보를 제공한다.
4. 방문한 노드의 원문 근거를 모으고 청크별 최대 3개 탐색 경로를 기록한다. 노드 라벨·간선 ID·관계·생성 근거·분기 조건을 함께 반환한다.
5. 물질/지침/절차/연락처 그룹을 순환 선택해 기본 최대 24개 그래프 근거를 반환한다.

기관 노드는 공통 소속을 나타내며 모든 부서의 연락처로 무제한 확장하는 허브로 사용하지 않는다. 업무별 서비스 노드를 통해 업무와 조직의 대응 관계를 유지한다. `(진입 노드, 방문 노드)`를 기록해 순환 간선을 처리한다.

`pipeline/config.json`:

```json
"graph": {"enabled": true, "max_hops": 5, "max_results": 24}
```

## API와 평가 연결

`pdf_pipeline.search()`는 `results`(벡터), `linked_results`(기존 연결), `graph_results`(그래프 근거), `graph_retrieval`(탐색 요약)를 반환한다. 검색 API는 계획 검색어마다 벡터 검색을 수행하고 원래 질문/대화 문맥으로 그래프 탐색을 한 번 수행한다.

벡터/물질/지침/절차/연락처 그룹에서 순환 선택해 최종 최대 20개 문서, 24,000자 예산으로 생성 컨텍스트를 구성한다. 그래프 경로도 프롬프트에 포함한다. 벡터 거리 필터는 벡터 결과에만 적용하며 그래프 결과의 거리는 `null`이다. 기관·시간·분류 필터는 벡터에서 검색된 구조화 청크에도 동일하게 적용한다.

일반 응답과 SSE `done` 응답에 `graph_retrieval.context_paths`를 제공한다. 현재 채팅 DB에는 기존 답변/출처 필드를 저장하며 그래프 경로는 신규 응답에서 제공한다. 프론트엔드 전용 그래프 뷰는 포함하지 않는다.

`POST /rag-query`와 `/rag-query/stream`은 기존 입력에 다음 선택 필드를 추가한다.

```json
{
  "prompt": "암모니아가 누출됐어요. 보고 절차와 연락처는?",
  "source": "pdf",
  "top_k": 5,
  "institution_scope": "lab_safety_manual_institution_unverified",
  "accident_classification": "non_major",
  "contact_at": "2026-10-26T11:00:00+09:00"
}
```

기관/분류 필드는 선택이며 `contact_at`도 생략할 수 있다. 시각을 제공하면 시간대 포함 ISO 형식을 사용한다. 예시 기관 ID는 현재 원문 연락망에 부여된 범위 ID다.

노트북 생성, 인용 ID 검사, RAGAS 평가, LangSmith 평가 자료는 그래프 근거를 포함하고 청크 ID로 중복 제거한다. 노트북 프롬프트 버전은 `safeops-safety-workflow-v7-internal-pictograms`이며 그래프 설정도 캐시 키에 포함한다.

## 실행

```bash
# 원문 추출과 그래프 생성: 외부 모델 호출 없음
.venv/bin/python -m pipeline.pdf_pipeline prepare

# 임베딩 전에도 실제 원문 그래프 조회 가능
.venv/bin/python -m pipeline.knowledge_graph \
  '암모니아가 누출됐어요. 보고 절차와 연락처는?' --prepared

# FAISS와 같은 버전으로 발행: 기존 텍스트 벡터 재사용
.venv/bin/python -m pipeline.pdf_pipeline --env-file .env build

# 현재 인덱스의 그래프 조회
.venv/bin/python -m pipeline.knowledge_graph '화재 대응 연락처' \
  --classification non_major --at 2026-10-26T11:00:00+09:00

# 벡터 + 그래프 검색
.venv/bin/python -m pipeline.pdf_pipeline --env-file .env search '암모니아 누출 보고'

.venv/bin/python -m unittest discover -s tests -q
```

기존 인덱스에 그래프 파일이 없으면 그 인덱스에 저장된 카탈로그·구조화·문서 연결 파일에서 메모리 그래프를 생성한다. 기존 인덱스 파일은 수정하지 않는다. 구 인덱스에 시간 정책 스냅샷이 없으면 시각 필터 사용 전에 `prepare/build`로 새 버전을 발행한다.

그래프 생성·조회에는 새로운 LLM/임베딩 호출이 없다. 기존 답변 모델 기본값은 `gpt-4o`, 문서/질문 임베딩은 `text-embedding-ada-002`(1,536차원)를 유지한다.

## 검증

실제 두 PDF로 노드/간선을 생성하고 임시 디렉터리의 테스트 벡터로 FAISS 저장·재로딩·통합 검색을 검사한다. 테스트 벡터는 검색 배선 검증용이며 의미 검색 품질 평가에는 사용하지 않는다. 추가 테스트는 hop 제한, 간선 제거에 따른 결과 변화, 순환 탐색 종료, 물질 경계, 기관/시간/분류 필터, 문서 연속 구간, 파일 해시, 구 인덱스 호환, API 컨텍스트와 그래프 인용을 검증한다.


## 공식 웹과 답변 누락 관리

`pipeline/safety_workflow.py`는 API와 노트북의 공통 근거 선택·답변 구성 정책이다. 병원·담당 부서·신체 주의·보고·대응 근거와 물질별 원문을 우선 예약한다. `coverage`는 항목별 출처 ID와 부족한 항목을 반환한다. 이는 **근거 존재 검사**이며 답변의 의미 정확성 점수가 아니다.

물질의 공식 건강·대응 정보가 부족하면 `pipeline/official_web.py`가 공개 CAS 번호로 검색한다. 위험기호 미확보는 추가 웹 검색 조건에서 제외하며 문서에서 확인한 위험기호는 위험성·주의사항을 연결하는 내부 근거로 유지한다. 답변에는 기호명·GHS 코드·확인 항목·미확보 문구를 출력하지 않는다. Naver `webkr.json`을 사용하며 사내 질문·연락망 전문은 검색어로 보내지 않는다. CDC CAS 색인으로 원문 페이지를 찾는 대체 경로가 있다. 현재 채택하는 본문은 CAS가 일치하고 First Aid 구간이 있는 **CDC/NIOSH 개별 물질 페이지**다. 검색 스니펫은 답변 근거로 쓰지 않는다. 한 질문에 최대 2개 물질/2개 원문을 보완하고, 네트워크 실패는 `web.status/errors`에 기록한 뒤 로컬 근거로 계속한다. URL·수집시각·원문 해시를 남기며 요청별 PDF 근거와 구분한다.

물질 질문의 답변은 직접 답 뒤에 물질 위험성, 신체 주의사항, 대응 및 보고, 담당 부서, 병원을 포함하도록 한다. 생성 모델이 전화번호를 생략하면 검색·시간/기관 필터를 통과한 연락 레코드만 출처와 함께 덧붙인다. 병원 자동 전화 연결이나 위치 기반 가까운 병원 검색은 수행하지 않는다. 현재 위치와 병원의 진료 가능 여부는 이 문서 연락망으로 확인할 수 없다.

확인된 그림은 가성소다·암모니아 2개 페이지이며, 모든 물질의 제품 SDS 분류를 확보한 것은 아니다. 나머지는 텍스트·공식 건강 정보를 보완하고 그림 미확보는 내부 coverage에 기록하고, 실제 대응에 필요한 농도·상태 조건만 설명한다. 그림 사전의 일반 의미를 개별 제품의 위험등급으로 승격하지 않는다.

별칭 근거: [CDC Hydrogen chloride](https://www.cdc.gov/niosh/npg/npgd0332.html). 검색 API: [Naver 웹문서 검색](https://developers.naver.com/docs/serviceapi/search/web/web.md).

현재 노트북과 API는 공통 근거 선택·답변 요구사항·연락처 보완을 사용한다. API의 선택적 LLM 검색 계획과 생성 temperature 0.2, 노트북의 단일 벡터 질문과 temperature 0은 아직 다르므로 노트북 점수를 서비스 전체의 동일 조건 벤치마크로 표현하지 않는다.

## 로컬 재검증 결과
