# SafeOps 통합 데이터 파이프라인

현재 확장: 여기서 작성한 구조화 자료를 속성 그래프로 컴파일하고 BFS 탐색 결과를 실제 답변 API에 전달한다. 구성과 실행은 [GraphRAG 안내](GRAPH_RAG.md)에 정리했다. 아래 기록의 API 미연결 설명은 확장 이전 상태다.

2026-10-23 사용자 요청에 따라 공휴일 API와 공휴일 목록 의존성을 제거했다. 시간 규칙은 Asia/Seoul 기준 월~금 09:00 이상 18:00 미만 주간, 그 외 야간이다. 문서의 '주간/야간' 원문은 보존하고 수치 시간은 사용자 규칙으로 구분한다.

## 현재 처리 흐름

원본 PDF 해시 확인 → pypdf 추출/정리 → 본문 청크 + 검토된 GHS 보충자료 + 출처 연결 절차/연락망 전사 → 임베딩 → FAISS 버전 발행 → 물질 식별 검색 → 상황별 근거 묶음.

- 원본 154페이지, 본문 366청크, GHS 보충 2개, 절차 경로 3개, 연락망 8개: 총 379청크.
- 기존 368개 벡터 재사용, 새 절차/연락망 11개만 text-embedding-ada-002로 임베딩했다. 2026-10-23 사용자가 해당 연락처 데이터 전송과 비용에 명시적으로 동의했다.
- 인식 참고 PDF는 검색 대상에서 제외한다. 원본/기존 인덱스/기존 실제 답변을 덮어쓰지 않는다.
- 단계별 준비본, 인덱스, 통합 검색 검증, 상황별 근거 묶음을 별도 저장한다. prepare/build를 분리해서 재실행 가능하며, 동일 텍스트 벡터는 재사용한다. 범용 자동 의존성 재실행 엔진은 아니다.

## 출처와 정규화

`pipeline/structured/procedure.json`은 원본을 대조한 19개 상자/16개 연결의 전사다. 신규 이미지 API 판독 결과가 아니다. 각 경로를 하나의 구조화 청크로 보존해 임의의 열 간 연결을 방지한다. 원본의 부서장을 부총장으로 바꾸지 않으며 반복 보고, 불명확한 조건과 미기재 담당자는 유지한다.

`contacts.json`은 8개 연락망 레코드다. 번호는 원문 문자열로 저장한다. 중복 번호의 다른 업무/시간, 나열과 '또는' 관계를 보존한다. 현행 유효성, 지역번호, 직통 담당자 연결은 확인되지 않았으며 자동 발신하지 않는다.

`source-pages.jsonl`에는 기존 native 추출문 전체를 보존했다. 개별 raw_text는 레이아웃 정리 전사로 표시했다. 좌표는 아직 검증되지 않아 null이며, 페이지/열/상자/연락망 행 ID로 출처를 찾는다.

준비본 및 인덱스에 `structure_snapshot.json`과 `material_catalog.json`을 함께 저장하고 해시를 검증한다. 구조화 원본 변경은 설정 해시 갱신과 prepare 재실행을 요구한다. 운영 시간 규칙은 PDF 사실과 분리되며 응답 근거에 정책 ID를 표시한다.

## 검색과 상황 연결

`pdf_pipeline.search`는 원문 이름/영문 이름/CAS번호로 물질 후보를 찾는다. 한 물질에 정확히 일치하면 해당 페이지로 벡터 검색 범위를 제한한다. 유사 부분문자열(질산/질산암모늄)은 구분한다. 이 카탈로그 50개 항목은 원문 식별자 후보이며 독립 검증된 화학물질 DB가 아니다. 별칭 추측이나 CAS/물질명 오류 자동 수정은 하지 않는다.

`incident_context.assemble`은 명시적인 사실 필드를 받아 같은 물질 페이지의 본문 전체와 그림 근거, 사고 경로와 관련 업무 연락처를 묶는다. 누출량/농도/사람 노출/화재/기관 등을 모르면 누락 정보로 남긴다. 중대/비중대 분류가 없으면 어느 쪽도 확정하지 않고 중앙 부서 경로만 제공한다. 분류가 주어져도 사용자 입력이며 검증된 법적 분류로 표시하지 않는다.

사람 노출 신호와 화재 여부는 분리한다. 대응용 근거를 수집하지만 위험도 진단, 물질별 응급처치 추정, 전문 소화 절차의 자동 실행 지시는 만들지 않는다. 소화 항목은 화재가 명시된 경우 요청 항목에 추가한다. 원문 페이지에는 다른 상황의 지침도 포함되므로 후속 답변 단계에서 적용 조건을 확인해야 한다.

기관 범위와 업무를 정확히 대조해 연락처 후보를 선택한다. 야간에 주간 번호가 제외되더라도 무관한 업무로 자동 대체하지 않는다. 역할 연결 미확인 연락처는 관련 업무 후보이며 보고 대상의 직통번호가 아니다.

## 실행

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m pipeline.pdf_pipeline prepare
.venv/bin/python -m pipeline.pdf_pipeline --env-file .env build
.venv/bin/python -m pipeline.pdf_pipeline --env-file .env search '가성소다 유해 그림문자와 누출시 주의사항'
.venv/bin/python -m pipeline.incident_context --facts evaluation/incident_demo_input.json --at 2026-10-23T11:00:00+09:00
```

build와 search는 임베딩 API를 사용할 수 있다. incident_context는 버전된 로컬 자료를 조합하며 외부 호출하지 않는다. demo 입력은 실제 사고가 아닌 가상 검증 상황이다. 기본 출력은 `pipeline_artifacts/incident-context/latest.json`과 `.txt`다. 이 출력은 근거 보고서이며 LLM 생성 답변이 아니다.

## 검증과 한계

31개 테스트가 통과했다. 추가된 검사는 시간 경계, 기관/업무 불일치, 연락처 중복 보존, 경로 분리, 미상 물질과 혼합 물질 구분, 표기 부분문자열 충돌, 소스 해시 변경 거부, 사고 분류 부재, 사람 노출/화재 분리를 다룬다.

`pipeline_artifacts/structure-review/integrated-search-verification.json`에 실제 임베딩 검색 4건을 저장했다. 가성소다와 암모니아 질문은 해당 물질 페이지로 제한됐다. 비중대사고의 오른쪽 경로는 top-5 안의 4위, 연구실 안전관리 연락망은 1위였다. 따라서 모든 질문이 첫 결과만으로 해결된다고 해석하지 않는다.

노트북 10절은 구조/시간 규칙, 11절은 실제 검색 결과와 가상 사고 근거 묶음을 보여준다. 평가 질문 12개는 평가 전용으로 분리한다. 이 인덱스에 대한 새로운 LLM 답변 생성과 RAGAS 재평가는 수행하지 않았다. 과거 점수는 과거 인덱스의 결과다.

남은 작업은 기관/전화번호 현재성 및 역할 연결 확인, 좌표 검토, 물질별 표/NFPA/지침의 추가 검증, 실제 응답 생성 경로와 프론트엔드 통합이다. 범용 OCR/병합 셀/화살표 자동 검출이 완성된 것은 아니다.

## 문서 간 연결 보강

`pipeline/document_links.py`가 준비본의 cleaned_text에서 14개 핵심 구간을 정확한 문자 오프셋으로 추출한다. 원문 페이지 28~31의 화재/누출/신체 오염/부상/응급환자/비상 준비를 분리한다. 29쪽 독성가스 절과 30쪽 상단은 명시적인 문맥 연속으로 연결하며, 같은 페이지의 다른 사고 유형과 합치지 않는다. 폐기물은 기관 매뉴얼과 제공 법률 PDF의 적용 범위/기본원칙을 따로 묶는다.

화재 31쪽 일반지침은 28쪽 제한조건과 함께 제공한다. 이 연결은 실행 순서나 전문 안전 판단이 아니라 함께 검토해야 할 출처 관계다. 피부 세척, 소화용 물, 용기 내 물 유입의 적용 대상을 혼동하지 않도록 후속 답변 프롬프트에 명시했다.

`document_links.json`은 준비본/인덱스에 버전과 파일 해시를 갖고 저장된다. 기존 379개 벡터를 모두 재사용하므로 이번 연결 추가에 새 임베딩은 0개다. 전체 154페이지의 주제 키워드 후보 목록도 저장하되 자동 적용 근거로 사용하지 않는다. 모든 문서 관계를 완전하게 검증했다는 뜻은 아니다.

일반 검색은 벡터 top-k를 `results`, 조건/연속 구간을 `linked_results`로 분리한다. 질문에 등장한 주제는 검색 힌트이며 실제 사고 사실로 간주하지 않는다. 노트북 답변 생성, 인용 ID 검사, RAGAS 평가 문맥, LangSmith 전송 자료는 두 근거 목록을 모두 포함하도록 수정했다. 실제 신규 LLM 생성/평가/업로드는 실행하지 않았다.

상황 묶음은 명시적 사실 필드 `spill_present`, `gas_leak_present`, `exposure_route`, `cut_puncture`, `fire_present`, `emergency_patient`, `waste_handling`을 사용한다. 알 수 없는 값은 null로 남긴다. 노출 경로가 없으면 피부 세척을 적용한다고 가정하지 않는다. 신체 오염에서는 병원 관련 연락처 후보, 화재에서는 소방 관련 업무 후보를 추가하되 현재성/기관 범위/직통번호 관계는 검증된 것으로 바꾸지 않는다.

PDF 30쪽의 `033-741-0114` 및 `구내: 2796`은 원문 관찰값으로 추가했다. 32쪽의 `741-0114`, `760-2796`과 동일한 발신 번호라는 결론을 자동 생성하지 않았다.

검증: 전체 테스트 36개 통과. 6개 가상 상황의 실제 로컬 근거 조합은 `pipeline_artifacts/structure-review/document-link-verification.json`과 `linked-scenario-*.json`에 보존했다. 노트북 12절에 확인 화면과 질문을 추가했다. 새로운 임베딩과 답변 생성 호출은 없다.
