# 세이프메이트 프론트엔드

Vue 3 + Vite 기반 로그인·채팅 UI입니다. Java·Python 서버 코드는 수정하지 않습니다.

`frontend` 디렉터리에서 실행합니다.

```sh
cd frontend
npm ci
npm run dev
```

`http://127.0.0.1:5173/`로 접속합니다. 진입점은 `frontend/index.html`입니다. 이전의 `python -m http.server` 대신 Vite를 사용해야 합니다. 로그인 화면의 **화면 미리보기**는 서버 없이 예시 대화와 브라우저 TTS를 제공합니다. 실제 로그인과 구분하며, 실제 자료 검색이나 업로드를 하지 않습니다.

## 디렉터리 구조

```text
frontend/
├── index.html
├── package.json
├── vite.config.js
└── src/
    ├── api/          # HTTP 요청 및 서비스별 API 연결
    ├── components/   # 재사용 가능한 화면 요소
    ├── pages/        # 로그인·채팅 페이지
    ├── styles/       # 전역 스타일
    ├── App.vue       # 인증 상태와 페이지 전환
    └── main.js       # Vue 진입점
```

## 기존 서비스 연결

Vite 개발 프록시가 브라우저의 같은 출처 요청과 인증 쿠키를 기존 서버에 전달합니다.

| 프론트 경로 | 기존 서비스 |
| --- | --- |
| `/auth-api/*` | `http://localhost:8080/api/*` |
| `/rag-api/*` | `http://localhost:8001/*` |
| `/voice-api/*` | `http://localhost:8008/*` |

로그인은 기존 `POST /api/login`, 상태 확인은 `GET /api/auth/check`를 사용합니다. 서버의 음성 화면 리다이렉트 대신 현재 Vue 채팅 화면을 엽니다. 비밀번호와 토큰은 브라우저 저장소에 저장하지 않습니다.

로그인 화면의 **회원가입** 버튼으로 가입 양식으로 전환합니다. 비밀번호 확인 후 기존 `POST /api/signup`에 폼을 전송하고, 가입이 완료되면 로그인 화면으로 돌아옵니다. 중복 아이디와 입력 오류는 화면에 표시하며 비밀번호를 브라우저 저장소에 저장하지 않습니다.

채팅 헤더의 토글로 **스트리밍**과 **한 번에** 응답 모드를 선택합니다. 스트리밍은 `POST /rag-query/stream`의 `status` → `token` → `done` SSE 이벤트를 `fetch()` 스트림으로 읽고, 한 번에 모드는 기존 `POST /rag-query` JSON API를 사용합니다. 두 요청은 모두 `{ prompt, source: "pdf", top_k: 5 }`를 전송합니다. 웹 검색과 웹/PDF 선택 UI는 제거하고 현재 백엔드의 문서 검색 경로로 고정했습니다. 현재 API는 단일 질문만 받으므로 화면의 이전 대화 내용은 다음 요청에 포함되지 않습니다. 대화 기록은 메모리에만 유지되고 새로고침 또는 로그아웃하면 사라집니다.

PDF 첨부는 기존 `POST /upload-paper`를 사용합니다. 백엔드 인덱스는 서버 전체에서 공유되며 사용자별 격리는 지원하지 않습니다. 새 파이프라인 전용 `safety` 경로로 전환하려면 해당 백엔드 연결이 필요하며, 이 프론트엔드 변경은 현재 제공되는 `pdf` 경로를 사용합니다.

## 음성 질문

로그인 후 마이크 버튼을 누르면 오디오를 WebSocket `/voice-api/stt/stream`으로 보내고, 로컬 Whisper의 중간 인식문을 입력칸에 실시간으로 표시합니다. 중간 인식문은 수정될 수 있으므로 이전 문장 뒤에 계속 붙이지 않고 현재 음성 부분을 교체합니다. 녹음 전 입력한 텍스트는 보존합니다.

**발화 후 3초 동안 조용하면** 녹음을 끝내고 최종 인식문이 도착한 다음 RAG에 질문을 한 번 자동 전송합니다. 최초부터 조용하거나 인식 결과가 없으면 검색하지 않습니다. 다시 말하면 3초 대기가 초기화됩니다. 마이크 버튼을 직접 눌러 중지한 경우에는 자동 전송하지 않으므로 수정 후 보내기를 누르세요. 연결·최종 인식 대기 중 버튼을 누르면 취소합니다. 최대 녹음 길이 60초에 도달해 종료된 경우도 직접 전송합니다.

HTTPS 또는 localhost/127.0.0.1의 최신 Chrome·Edge, 마이크 권한, AudioWorklet, 실행 중인 STT 서버와 유효한 로그인 쿠키가 필요합니다. 미리보기에서는 음성을 전송하지 않습니다. 녹음·권한 대기·변환 중에는 일반 전송과 화면 전환을 막고, 컴포넌트 종료 시 마이크·연결을 정리합니다. WebSocket 음성은 서버 메모리에서만 처리하고 종료 시 버리며 파일로 저장하지 않습니다. 기존 파일 업로드 STT API도 유지됩니다.

음성 인식은 로컬 Whisper이므로 음성 인식 API 토큰 비용은 없습니다. 서버 CPU·메모리는 사용합니다. Whisper가 매 토큰을 직접 전달하는 방식이 아니라 새 오디오를 일정 간격으로 재인식해 중간 문장을 전달하므로 반영 속도는 서버 성능에 따라 달라집니다. RAG 호출은 인식 조각마다 하지 않으며, 최종 질문의 기존 검색·답변 생성 비용만 발생합니다.

무음은 오디오 RMS 임계값(기본 0.012)으로 감지하며 최초 200ms 이상의 음성 크기가 확인되어야 동작합니다. 배경 소음이나 매우 작은 목소리는 감지에 영향을 줄 수 있습니다. `speechAudio.js`의 `SilenceDetector` 설정으로 조정할 수 있습니다.

Vite 프록시는 WebSocket 업그레이드(`ws: true`)를 전달해야 합니다. 컨테이너 사용 시 `docker compose up -d --build voice frontend`로 갱신하세요. 허용 접속 출처는 `STT_ALLOWED_ORIGINS`이며, Compose는 프론트엔드 호스트 포트를 기준으로 설정합니다.

`npm test`는 실제 마이크·서버 호출 없이 가입 API 응답, 문서 검색 고정, 녹음 상태·권한 거부·STT 오류·자원 해제, PCM 변환, 3초 무음, 중복 자동 전송 방지를 검증합니다. 음성 프로토콜 테스트는 `voice-ai_code/.venv/bin/python -m unittest discover -s voice-ai_code/tests -v`로 실행합니다.

답변 아래 **답변 듣기**는 `POST /tts/`에 `text` 폼을 보내고, 반환된 `/uploads/…` 음성을 재생합니다. 클릭하면 재생을 중지할 수 있습니다. 기존 서버가 동일한 음성 파일명을 사용하므로 다중 사용자 동시 재생은 별도 백엔드 개선이 필요합니다. 음성 오류는 화면에 표시합니다.

## 빌드

```sh
npm run build
```

`dist/`를 생성합니다. Vite 프록시는 개발 전용입니다. 배포 시 웹 서버에서 위 세 경로의 리버스 프록시를 설정해야 합니다. `npm run preview`는 정적 빌드 확인용이며 실제 API 프록시를 제공하지 않습니다.

실제 로그인에는 인증 서버의 `DB_PASSWORD`, `JWT_SECRET` 실행 환경 설정이 필요합니다. Java 인증 서버의 JWT 키는 기존 음성 서버의 검증 키와 일치해야 합니다. 로컬 실행용 `.cache/runtime/` 스크립트·설정은 Git에 포함되지 않습니다.

### 답변 번역 및 음성 듣기

로그인 후 채팅 상단의 **답변 음성 언어**에서 한국어·영어·중국어·일본어·베트남어를 선택합니다. 한국어는 **답변 듣기**, 외국어는 **번역하고 듣기**를 누르면 재생됩니다. 외국어 번역문은 한국어 원문 및 근거 아래에 함께 표시됩니다. 언어를 바꾸면 재생이 중지되고, 해당 언어로 다시 듣기를 요청할 수 있습니다. 미리보기 모드는 기존 한국어 브라우저 음성만 지원합니다.

기존 `OPENAI_API_KEY`를 사용하며, 선택 설정은 다음과 같습니다. Docker에서는 루트 `.env`에 추가하고 `docker compose up -d --build voice`로 반영합니다.

```dotenv
TRANSLATION_MODEL=gpt-4o-mini
TTS_MODEL=tts-1
TTS_VOICE=nova
```

`POST /voice-api/tts/`에 폼 필드 `text`, `target_language`(`ko` 기본값)를 전달하면 `original_text`, `translated_text`, `target_language`, `file_path`가 반환됩니다. 한국어 답변을 외국어로 번역하는 기능이며, 질문 입력 언어나 화면 전체의 언어를 변경하지 않습니다. 원문 및 번역문은 각각 4,096자까지 지원하며 초과 시 안내합니다. 번역 실패 시 음성을 생성하지 않습니다. 번역문은 현재 화면에서만 유지되며 대화 재접속 시 다시 생성해야 합니다. 번역과 음성 생성에는 API 사용료가 발생합니다.
